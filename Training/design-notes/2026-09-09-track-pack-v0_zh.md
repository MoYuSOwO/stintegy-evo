# 赛道包格式 v0（设计定稿，零代码）

**一个文件，分层，层可选；一个格式，两个消费者，各取各层。**

## 一、层

| 层 | 内容 | 现状 |
|---|---|---|
| `meta` | 名称、正式圈长、赛距圈数、发源地与授权 | 散在 README 与工厂方法里 |
| `centerline` | 现行 CSV 的内容（x, y, 左右宽） | `Core/Track/Data/*.csv` 入层 |
| `elevation` | 高程/坡度剖面 | 手写剖面迁入地皮 |
| `surface` | 表面分区逐赛道覆盖 | **缺省继承全局边缘语法**，不写即不覆盖 |
| `grid` | 发车格配置 | `TrackFactory` 硬编码入包 |
| `scenery` | **可选**：资产引用 + 摆位（桩号 / 横向偏移 / 旋转 / 缩放）、植被区域、背景 | 尚不存在 |

`surface` 那一行是刻意的：**不写就是继承**。边缘语法（柏油 → 路肩坡 →
草）是全局默认，一条街道赛道只需要写下它与默认不同的那几段，而不是把
整条赛道的表面重抄一遍。**默认必须是对的，覆盖才配是稀疏的。**

## 二、读取契约

- **Core 只读物理各层**（meta / centerline / elevation / surface / grid），
  **整块跳过 `scenery`**——运行时不为装饰分配一个字节。
- **表现层读 `meta` + `scenery`**；几何照旧走 `TrackData`，表现层不自己
  解析中心线，避免两份几何各自漂移。

**辖区的修正**：先前说"景观不进 Core"，说法不准。**不进的是运行时，不是
文件。** 装饰和物理住同一个文件是对的——它们描述的是同一条赛道，分家会
立刻产生"资产摆在赛道 3800 米处，可那份几何已经改了"这种对不上的账。
分的是**谁在运行时把哪几层读进内存**。

## 三、前向兼容铁律

**不认识的层一律保留并忽略。**

一个旧版本的读取器遇到新层，既不许报错，也不许丢弃——它要原样带着走，
这样一个包经过旧工具的手之后仍然是完整的包。这条是为"模组作者用的工具
版本永远比引擎旧"准备的，不是为我们自己准备的。

## 四、押后的施工（触发时搬家，不重造）

加载器迁移——把 `TrackFactory` 里硬编码的海拔与发车格搬进包——押
**模组/表现层时代**。触发条件是二者之一先到：第三方赛道模组要能被加载，
或表现层需要景观。届时是**搬家**，不是重写：数值原样搬过去，搬完的验收
是"每条赛道逐位构建出与搬家前相同的 `TrackData`"。

`TrackBuilder` 的定性不变：**进口流水线是本体**（测绘点 → 控制点 →
样条 → 航向清洗 → 重采样 → 缓冲区），`AddStraight` / `AddTurn` 那套
segment API 转为**测试道具厂**编制——它造的是给测试用的简单布局，不是
产品赛道的来源。
