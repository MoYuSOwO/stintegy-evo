# 参数喂食教义：车辆描述块的未来占用者

记录日期：2026-09-12。起因：用户问"轮胎参数也会变的话，是不是也要喂"。
答案是要，而且观测协议已为此留位。本文定原则、列占用者、记一个已知的编码债。

## 一、现状（对树验证）

- `DirectDriveObservation.VehicleDescriptorSize = 8`：车辆描述块已预留，
  当前显式写零（"Ground held for the setup vector, and nothing in it yet"）。
  注释原则已定：**"Ability deceives the interface; setup informs the network"**
  ——能力是接口上的隐形失真（车手不自知），设定是车手能感知并适应的可见状态。
  参数属于后者，喂。
- 比例纪律已吸收一大类参数变化：轮载 ÷ 本车静态角载（"在任何车上静止读 1"）、
  磨损 0–1 分数、能量比例槽。**是尺度（scale）的参数，被比例自动中和。**

## 二、什么必须喂：改变形状与速度的参数

比例吸收不了的，是改变动力学**形状**或**速度**的数字，它们就是描述块的占用者：

1. 配方抓地水平（相对基准的系数）；
2. 温度窗位置与宽度（见第四节的编码债）；
3. 磨损速率（分数通道告诉你在哪，不告诉你走多快）；
4. 平衡（FrontPeakSlipAngleRatio 一族——调校屏幕迟早暴露它）；
5. 动力曲线特征（衰减起点等，与资源槽互补）。

**喂物理参数的归一值，不喂配方 ID / one-hot。** 网络只会插值：
mod 配方只要数字落在训练包络内，没见过也能开——one-hot 杀死插值，
参数向量保留它。这就是内容包生态的承诺：
**"你的车若住在训练包络里，就免费获得一个称职的车手。"**

## 三、教义闭环：喂 = 随机化

"存在但从不变化的通道 = 车手对它失明"。喂而不变，等于没喂。
所以参数喂食与**参数随机化课程**是同一件事的两半：世界状态随机化
（胎况/电量/抓地/气温，已实施）之后，参数随机化是下一根轴。
成本意识：配方是离散的两三个点，不是连续统，稀释代价很小。

本周学费即证据：删双重计热/计磨改变了磨损与发热参数，母本必须付一炉
适配——正因这些数字是烤进反射里的隐形常量。若磨损速率是被喂且随机化过
的通道，包络内的重标定本可当天生效。（诚实注脚：结构性修改——删除一个
重复项——改的是映射本身，即便喂了参数也躲不掉部分适配；喂参数免除的是
**包络内的调参**，不是**换物理**。）

## 四、已知编码债：温度通道是绝对刻度

胎温现为 `SurfaceTempC / TemperatureScale`（全局常量），不是窗口相对。
多配方时代两条路：
- (a) 改窗口相对编码——语义变更，等价于一次维度作废，须赶代际班车；
- (b) 描述块喂窗口位置+宽度，让网络自己做减法——保住检查点连续性。
倾向 (b) 起步、(a) 留给下一次本就要作废的代际。届时裁决。

## 五、配方随车出厂（用户裁决，2026-09-12）

轮胎家族**绑定车辆、在内容包里声明**，不做自由混装。一车一家族
（两三个干胎配方，雨胎归天气门），玩家与策略的自由度在家族**之内**
（用哪个配方、何时换），家族本身出厂即定。三层理由：

1. **物理**：胎与车是共同标定的（质量、下压力、轴距决定胎看到的载荷
   与温度，窗口和磨损率是对着这台车调的）。现实同构：轮胎按系列配给,
   没人把 F1 软胎装上 F2。自由混装 = 组合标定灾难 + 物理胡话；
2. **架构**：声明式内容包的自然延伸——car 目录下声明其 TireConfig 家族,
   扫描聚合、无中央清单，与 DriverCatalog 同一教义；
3. **训练**：一台车的参数包络 = 它声明的家族凸包加余量。描述块只需
   张成本车家族，不必编码"所有可能的胎"——参数喂食的范围因此又小又清。
   mod 车带自己的家族：数字落在某母本包络内则白得车手，否则接力再训。

**细化一（同日）：家族分两层——谱系与配给。** 车出厂声明**谱系**
（供应商全季配方全集），每场比赛声明**配给**（谱系内两三个点）。
训练覆盖谱系全域，逐站换配给零再训。

**细化二（同日，用户裁决，推翻本笔记初版的"流形采样"）：
支撑集是箱体，不是流形。** 目标是把车手练成轮胎参数的连续函数：
**箱体内任意坐标都要能开**（"随便调一个参数都要开，当然是有限的调"）。
初版"沿软度流形相关采样"是支撑集截断——mod 与调校屏幕必然探索
流形外的组合（软胎抓地 + 硬胎磨损），只训流形就是在参数轴上重演
240 秒盲区。流形思想降级为**采样密度先验**（现实组合附近抽得密），
永远不得作为支撑边界；支撑 = 全箱体。

**箱体的边界在类型系统里已经画好**（2026-09-12 对树验证）：
- `TireConfig` 的 `const`（约 22 个：热指数、冷却/传导率、热时间尺度、
  过限率等）= 模型结构，编译器保证 mod 内容根本无法触碰——
  "不能轻易动的物理参数"由语言强制；
- `{ get; init; }`（BaseMu、窗口上下沿、冷/热抓地损失曲率、磨损线性
  损失、悬崖起点/深度、发热率、模式使用阶梯等）= 可调数字面，
  即训练箱体的维度。"物理是一个、车带数字"从此有精确定义：
  数字 = init 面。
- 待定义的只剩**每维的界**：训练过的箱体即发布契约
  （"此范围内的胎，车手保证会开"）；包校验对出界的 mod 胎
  标注"需接力"而非拒载。界从"有限的调"起步，代际班车加宽。

代价诚实账：全箱体比五个离散配方课程贵。缓解：界起步收窄、
高杠杆维度其实很少（BaseMu、窗口、磨损率）、容量测试本就排队、
且世界状态随机化四五根轴的先例证明这类课程买得回泛化。
**注意描述块预算**：8 通道 vs init 面 15+ 维——首批入住按行为杠杆
挑选；若 8 席不够，扩席 = 改维度 = 赶代际班车，届时裁决。
先例：赛道泛化（雪邦未训而能跑）证明"喂它、变它，网络就从
背答案转向读题"；参数轴是同一招的第二次使用。

## 六、时序

- 二幕：不动。单车单配方，描述块保持零，网络正确地忽略它。
- 首次占用：配站/配方时代（配方=参数变化的天然入口）。占用已预留的零通道
  **不改变观测维度**：旧检查点在此处只见过零，权重从未被训练过（梯度恒零），
  热启动时新值经随机初始权重进网 ≈ 噪声注入，适配炉消化——远好于改维度作废一切。
- 描述块注释的代际规则照旧："检查点已作废的世代，是改维度唯一免费的时机。"
