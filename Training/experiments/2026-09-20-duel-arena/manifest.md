# 1v1 对偶擂台管线（feature/duel-arena）

工单来自协调方转达的用户批准：让 `solo=false` 复活，对手由冻结检查点驱动。**只做管线，不做奖励设计**——奖励形状、课程、episode 起点分布一律未动。

基线 era/world-v3 `bbda072`，分支 `feature/duel-arena`，工作树 `.worktrees/duel-arena`。活炉工作树 `.worktrees/bake-parent3b` 全程未碰。

## 1. 环境：第二个座位

`DirectDriveDuelEnvironment` 的 `!solo` 拦截撤掉。对手不是脚本，是同一套学习接口上的第二辆车，每步从外部接一份 `DriverInput`：

- `Step(egoAction, opponentAction, egoObs, opponentObs)`，两份动作在任何东西移动之前都提交，所以谁的操作都不比对方新一步；两份观测在同一区间末端采样。
- `Reset/ResetTrack/ResetHeldOut/ResetScenario` 各加一个对手观测重载；空 span 就是"这是 solo"。
- 对手有自己的装配面：自己的 `CarConfig`（钳制强度取自隐藏课程自己的抽样）、自己的轮胎（含 `TireStressScale`）、自己抽的围场指令、自己的预算锚点、自己的感知噪声流。
- 奖励仍然完全是 ego 的。`RelativeProgressReward` 的现成开关按原样接通（`_solo ? 0 : 0.1f * (egoProgress - opponentProgress)`），`TimeoutOutcome` 同理。对手的比赛不给任何人发奖励。

**抽样顺序**：对手的每一次抽样都排在 solo 会做的全部抽样之后，所以打开对手不会移动 solo 的随机流。

## 2. 协议 v6

握手多一个字段：每车道座位数（solo 1，对偶 2）。每车道的观测与动作按座位排列，ego 永远是本车道第一个座位——solo 的布局就是对偶布局少了第二个座位，不是另一种形状。

奖励、终止、记分板字段仍是每车道一份（只有 ego 在训）。对偶多附一个记分板字段：**带符号领先距离（米，对手领先为正）**。它不是观测也不是奖励，和圈速距离、旋转数、四轮出界秒数同等地位——否则只能拿 ego 那份被缩放、截断、加噪的观测去反推谁赢了。

宿主 CLI 默认改为 solo，对偶要显式 `--duel`。旧默认是 `solo=false`，但环境当时对它抛异常，所以没有调用者能用；现在它会真的多放一辆车并改变每条消息的形状，必须点名要。

## 3. train.py 的对偶臂

- `--duel`、`--opponent-checkpoint`、`--opponent-pool K`（桩）。
- 对手 = `opponent.FrozenOpponent`：同一套 actor 网络从检查点载入，`act` 在 `@torch.no_grad()` 下取确定性动作，网络置 eval，永不更新。
- 学习器只训 ego：奖励、终止、回放缓冲区都只有 ego 的。
- `latest-K` 池是**明标的桩**：`pool_candidates` 列出某 tag 最新 K 个 eval 检查点，`draw_from_pool` 永远取最新那个。按 episode 重抽、以及多久重抽一次，是训练设计问题，本工单不裁。
- eval 记分板加最小对局列：`对局 胜/局  差距 ±m  接触 N 步`。胜负与差距读宿主的领先距离（取本步结束、重播种之前的值），接触数是本步接触罚不为零的车道数。

## 4. 设计裁定：对手槽的规划通道恒零

已写进 `DirectDriveObservation` 的 XML 注释。要点：对手打算做什么是私有的——旧的规划通道取自只有已退役解析驾驶员才发布的交通运动计划，新契约上没有任何控制器发布计划；能诚实知道的（相对位置、朝向、接近率、是否并排）已在前十二个通道里，其余由 ego 自己推断。同时契约保持 457 通道、每块原位，**母本权重即插即用**：solo 烤出来的母本直接坐进第二辆车，不需要任何转换。

## 6. 吞吐探针（同机实测，`duel_probe.py`）

纯环境+管道，不含学习器。**机器上同时有母本炉在烧**（parent3k，batch 64），两臂都在同样的争用下测，数字要连这句一起引。机器 Mac16,12，10 核，负载约 3.5–4.9。

| batch | solo | duel | 每车道代价 | 每车吞吐 |
|---|---|---|---|---|
| 16 | 3986 车道步/秒 | 3391 车道步/秒 | 1.18× | 6782 车步/秒（solo 3986） |
| 64 | 8043 车道步/秒 | 5074 车道步/秒 | 1.59× | 10148 车步/秒（solo 8043） |

读法：一条对偶车道比一条 solo 车道贵 1.18–1.59 倍，不是两倍——第二辆车共享赛道采样与帧捕获。按"模拟出来的车"算，对偶的吞吐反而更高（batch 64 时 1.26 倍）。batch 越大代价越接近两倍，因为并行度已经吃满，原始数据在 `throughput-batch16.json` / `throughput-batch64.json`。
