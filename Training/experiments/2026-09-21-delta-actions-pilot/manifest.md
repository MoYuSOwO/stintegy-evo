# 增量动作试点：交付说明

单变量实验，era 内部。分支 `feat/delta-actions-pilot`，基线 `era/world-v3@44925cb`。master 与 Core 零改动，物理/奖励/课程/协议/观测维度一律未动。活炉 4f 全程未碰（检查点只读复制出来做基线探针）。

## 改动最小集

1. **契约**：`--delta-actions` 打开后，`action[0]` 由"要保持的曲率"改为"这一拍把命令移动多少"。座位（`DirectDriveController`）持有积分器，`κ_cmd ← clamp(κ_cmd + a0·Δcap, −1, 1)`，episode 重置清零。纵向动作维持绝对制。
2. **Δcap 标定（按车算，不是挑的）**：车轮自己从正中到锁位要 `MaxSteerAngleRadians / SteerRateLimitRadiansPerSecond = 0.8 / 1.047 = 0.764 s`，15 Hz 下是 11.46 拍；命令全程宽 2 个单位，故

       Δcap = 2 / 11.46 = 0.17450

   即命令横越全程所需时间 = 车轮走到锁位所需时间。**齿条仍然是处处的约束者**，所以可达轨迹集合与现状一致——这是"只改动作释义、不改车能做什么"的保证。代码里由 `DirectDriveController.CurvatureDeltaCap(config, decisionHz)` 从配置算出，不是魔数。

   *口径说明*：工单原文按"0.8 ÷ 1.047 ≈ 0.76 s ≈ 11.5 拍"给出 ≈0.174，我按此实现。另一种读法是拿"锁到锁"（1.6 rad，1.53 s，22.9 拍）对齐命令全程，得 Δcap = 0.0873，命令与车轮速度严格相等。若试点显示 0.1745 下平滑不足，**减半是唯一旋钮**，其余不动。

3. **积分器对策略可见**：写在 ego 块第 10 号通道——那个通道的含义一直就是"上一拍命令了什么"，绝对制下是动作本身，增量制下就是手里握着的命令。457 维不变、无通道改义、无占位通道被借宿；上一帧副本让策略能自己还原出上一拍的增量。

   *与工单的差异*：工单让我把 κ_cmd 塞进"零填充占位通道"。我没有这么做，理由是那些零通道是**按铁律四写"缺席"的静态量**（电池车的第二资源槽恒 (0,0)），借宿会让"缺席"和"借来的读数"混在一个通道里；而 ego+10 的语义与 κ_cmd 完全重合，不需要任何新解释。若你坚持占位口径，改一行即可。

4. **回归锚**：`--delta-actions` 关闭时逐位等价现状。宿主套件 60 条全过，含 `SoloFingerprintTests`（三赛道 × 两课程档 × 240 步固定脚本的逐位指纹）。老配方 smoke 一条已跑通。

## 试点测试（`DeltaActionTests`，5 条）

- Δcap 与齿条对账（0.17450，且反推回 0.764 s）。
- 持续满增量 6 拍推满量程、随后零增量**保持**（直线不再需要每拍下令）、反向按同速率退回。

## 抖舵探针（`Training/python/jitter_probe.py`）

数的是**车实际收到的命令**（从观测 ego 块读回），不是原始动作——增量制下数动作只会数到"策略多久改一次主意"。只在直道计数（|横向加速度| < 2 m/s²），弯道另报。

现役冠军 `evalparent4e-3950000`（绝对制）实测：**直道 9.88 翻转/秒**，弯道 10.75——与族谱考古的 ~10/秒 吻合，基线对上了。

探针自检：拿同一个绝对制检查点按增量制解读，命令翻转率降到 1.55/秒——证明探针量的是命令而非动作。**同时暴露一件必须写下来的事：这个筛子可以被"开不了车但命令平滑"的策略通过**（那次自检旋转 20 次）。所以数字只是必要条件，不是充分条件。

## 验收（按追加裁定）

1. 烤到 400–500k 步，对 eval 检查点跑探针：**直道 <3/秒 → 进人眼终审；5–10/秒 → 直接毙，回 v4 链；中间带 → 延长观察**。
2. **最终门禁是用户在观赛台亲眼看**：直道上看不见乱抖才算通过。数字不过就不浪费人眼。
3. 驾驶基本面（能完圈、配速带成形）只作 sanity，不作判据——但结合探针自检那条，sanity 必须真的看一眼，否则筛子会放行一个开不了车的平滑命令。
