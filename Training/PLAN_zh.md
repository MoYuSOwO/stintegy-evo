# 学习司机训练计划

本计划是"学习司机"时代的工作地图：让一个学习出来的策略直接驾驶参与完整物理仿真的赛车，
替代分层规则栈中的驾驶决策部分。计划的每一条都来自一个明确的设计裁决，裁决理由随条目记录，
以便后来者（包括未来的我们）知道哪些是原则、哪些只是当时的权衡。

## 一、接口：端到端物理控制

**动作空间（2 维，30 Hz）**：`DriverInput` 的前两个字段——期望曲率与期望轴加速度。
本仿真的控制接口天然理想化：曲率指哪打哪、加速度近似线性，因此"端到端"在这里
不需要学习方向盘与踏板的物理，只需要学习驾驶决策本身。

- 曲率：策略输出 [-1,1]，按车辆 `MaxCurvatureRequest` 线性缩放；
- 加速度：策略输出 [-1,1]，负半轴按最大制动、正半轴按当前驱动上限缩放；
- 除物理执行器上限外**不设任何行为钳制**——没有跟车距离、没有让行剧本、没有过渡曲线。

**基线作参考，不作底座**：解析规划器（赛车线 + 速度规划）继续运行，但它的建议只写进
观测（"教练的建议"），不叠加到动作上。策略想抄就抄、想背离就背离，没有人抢方向盘。
不采用残差方案的原因：缠斗中基线会坚持赛车线，残差策略必须持续对抗基线才能保持
非常规线路，这种对抗本身是学习负担。

## 二、安全：车的物理 + 赛会判罚，没有防撞层

裁决过程记录（重要，防止将来有人"好心"把层加回来）：

1. 碰撞兜底存在逻辑死结：调得早必然误伤故意的贴身驾驶（有用程度=冤枉好人的程度），
   调得准则物理上已不可避免（精准=无用）；且对手可以武器化你的兜底。
2. 真实赛车运动是"零防撞层"运行了一百年的存在性证明：ABS/TC 管的是自体物理，
   避撞是车手技能，事后归赛会管辖。
3. 因此运行时只保留两类东西：
   - **车的自体物理**：稳定性控制、牵引力控制（现有 `StabilityControlLaw` 等，属于"车"）；
   - **赛会**：损人行为（责任接触、挤人出赛道）以判罚进入训练奖励，将来进入比赛规则。
4. "零接触"退役为脚本司机时代的验收标准；学习司机时代的标准是
   **责任事故率与真人水平相当**。接触有代价、有裁决、有概率，不再是系统保证。

**自费的极限不惩罚**：抓地极限、轮胎消耗等代价由物理与圈速自然定价，触发即最优的
场合到处都是，不设人工惩罚。**损人的判罚才惩罚**：责任接触、挤压，由赛会（训练奖励）裁定。

**模式合规**：电池模式在物理层硬限（等同真实 ECU 功率图，保持现状）；轮胎模式是管理
指令，进观测 + 进奖励——每档模式对应磨损/温度预算，超预算扣分。训练出的是"服从
pit wall 的车手"，策略游戏的循环因此成立。

## 三、观测：约 300 维，track-agnostic

**防泄露铁律**：同一物理局面出现在任何赛道，观测必须逐位相同。禁止绝对 s、全局坐标、
赛道长度、圈数、赛道身份。验收：多赛道训练、留出赛道（Sepang 风格）评估。

| 块 | 内容 | 维数 |
|---|---|---|
| 前方几何 | 对数间隔 17 点（2→600 m），每点自车系 (x, y) + 半宽 + 曲率 | 68 |
| 自车状态 | 速度、纵/横加速度、横摆率、侧偏、道路航向差 (sin,cos)、横向位置、两侧边距、上一拍执行的曲率与加速度 | 12 |
| 轮胎与电量 | 四轮 表面温/核心温/磨损 + SoC | 13 |
| 模式上下文 | 轮胎模式、电池模式、超车权 | 3 |
| 气动 | 尾流、下压力损失、脏空气 | 3 |
| 教练参考 | 建议曲率、建议加速度、前 12 个几何点上的自由计划速度 | 14 |
| 对手 ×6 | 在场标志、自车系相对位置/速度、航向差 (sin,cos)、速度、道路横向位置、纵/横向间距、并排标志、发布计划 1s/2s 未来 (自车系) | 96 |
| 动态帧差 | 自车 + 对手动态块的上一拍快照（帧差信息） | 108 |
| **合计** | | **317** |

不给赛车线几何本身——线让策略自己从原始几何学出来（"涉及线路问题"所以网络稍大）。
配速参考（自由计划速度）保留为纯参考；训练后期做开/关消融，若留出赛道成绩显示
其成为拐棍则砍除。不给对手的模式——现实中读不到对手引擎图，部分可观测是合理的。

长时程信息不用 RNN：短时看帧差，前瞻看对手发布计划，行为风格看手工 EMA 特征
（后续按需加入，每对手 2-3 维）。理由：运行时成本不是问题（GRU 也只有 GFLOP 级），
真实代价在训练管线复杂化（序列回放、burn-in、隐状态过期）与不可审计。

## 四、网络与性能预算

- MLP：317 → 512 → 512 → 256 → 动作头，约 70 万参数；
- 推理约 1.4 MFLOP/次；20 车 × 30 Hz ≈ **0.85 GFLOP/s**，CPU 单核零头，运行时无 GPU 需求；
- 项目性能前提（README）：二十辆车同场、CPU 实时——本预算满足并留有余量。

## 五、训练

- **算法**：连续控制用 off-policy RL（SAC 系）。遗传算法保留为低维决策策略的廉价基线，
  不用于高频控车（信用分配与样本效率不匹配）。
- **奖励**：赛程推进 + 终局名次/时间差 + 赛会判罚（负）+ 模式预算合规（负）。
- **课程**：
  1. 单车跑圈——毕业标准：圈速追平解析基线（清晰、可自动判定）；
  2. 对局 vs 脚本司机（现有规则栈整套充当陪练与对照组）；
  3. 自博弈。
- **数据增广**：赛道左右镜像 + 动作镜像，数据翻倍并灌入"左右弯等价"先验。
- **确定性**：仿真逐位确定，同种子必须复现同轨迹——回归与调试的地基，
  管线中以测试钉住。

## 七、里程碑与验收

1. **管线打通**：Python 客户端经协议驱动环境跑随机动作，观测/奖励/终止全链路无损；
2. **基线复现**：教练直通策略（照抄观测中的建议）在 Simple 赛道完赛且不出赛道，
   里程达到 `ReferenceLineDriver` 的 85% 以上（教练取分段峰值曲率，天然保守约一成，
   该钉子只验证接口无损，性能标准在下一条）；
3. **单车毕业**：训练策略圈速 ≥ 解析基线，多赛道成立，留出赛道不塌；
4. **对局毕业**：vs 脚本司机（Attack vs Normal 决斗）超车成功率 ≥ 规则策略基线，
   责任事故率低于设定阈值；
5. **自博弈阶段**：另行计划。

## 八、非目标（本阶段明确不做）

- 防守策略的规则实现（学习司机应自然习得防守；规则版防守只在陪练需要时考虑）；
- RNN / Transformer 序列模型；
- GPU 推理路径；
- 视觉输入；
- 真人驾驶输入。
