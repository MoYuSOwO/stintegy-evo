# 学习司机训练计划

本计划是"学习司机"时代的工作地图：让一个学习出来的策略直接驾驶参与完整物理仿真的赛车，
替代分层规则栈中的驾驶决策部分。计划的每一条都来自一个明确的设计裁决，裁决理由随条目记录，
以便后来者（包括未来的我们）知道哪些是原则、哪些只是当时的权衡。

> **状态（2026-08-30）**：里程碑 3「单车毕业」已达成。300k 步、单种子，学习司机在留出
> 赛道雪邦跑到解析基线的 **95%**，在两条 simple 上**超过**解析司机（104% / 102%），
> 八条赛道零退赛零撞墙。观测重写为 452 维（路面几何 + 按秒缩放的视界 + 被罚量可见），
> 熵系数改回自动调节。详见 [七之一](#七之一单车毕业成绩300k-步单种子)。

## 一、接口：端到端物理控制

**动作空间（2 维，30 Hz）**：`DriverInput` 的前两个字段——期望曲率与期望轴加速度。
本仿真的控制接口天然理想化：曲率指哪打哪、加速度近似线性，因此"端到端"在这里
不需要学习方向盘与踏板的物理，只需要学习驾驶决策本身。

- 曲率：策略输出 [-1,1]，按车辆 `MaxCurvatureRequest` 线性缩放；
- 加速度：策略输出 [-1,1]，负半轴按最大制动、正半轴按当前驱动上限缩放；
- 除物理执行器上限外**不设任何行为钳制**——没有跟车距离、没有让行剧本、没有过渡曲线。

**基线作参考，不作底座**：解析规划器（赛车线 + 速度规划）继续运行，但它的建议只写进
观测（"教练的建议"），不叠加到动作上。策略想抄就抄、想背离就背离，没有人抢方向盘。
不采用残差方案的原因：缠斗中基线会坚持赛车线，残差策略必须持续对抗基线才能保持
非常规线路，这种对抗本身是学习负担。

## 二、安全：车的物理 + 赛会判罚，没有防撞层

裁决过程记录（重要，防止将来有人"好心"把层加回来）：

1. 碰撞兜底存在逻辑死结：调得早必然误伤故意的贴身驾驶（有用程度=冤枉好人的程度），
   调得准则物理上已不可避免（精准=无用）；且对手可以武器化你的兜底。
2. 真实赛车运动是"零防撞层"运行了一百年的存在性证明：ABS/TC 管的是自体物理，
   避撞是车手技能，事后归赛会管辖。
3. 因此运行时只保留两类东西：
   - **车的自体物理**：稳定性控制、牵引力控制（现有 `StabilityControlLaw` 等，属于"车"）；
   - **赛会**：损人行为（责任接触、挤人出赛道）以判罚进入训练奖励，将来进入比赛规则。
4. "零接触"退役为脚本司机时代的验收标准；学习司机时代的标准是
   **责任事故率与真人水平相当**。接触有代价、有裁决、有概率，不再是系统保证。

**自费的极限不惩罚**：抓地极限、轮胎消耗等代价由物理与圈速自然定价，触发即最优的
场合到处都是，不设人工惩罚。**损人的判罚才惩罚**：责任接触、挤压，由赛会（训练奖励）裁定。

**模式合规**：电池模式在物理层硬限（`CalculateDriveAccelLimit` 直接卡驱动加速度，
等同真实 ECU 功率图，保持现状）；轮胎模式**物理层完全不限制**——那个抓地力比例只进了
规划器，所以学习司机能在 Protect 下榨满抓地力。判罚口径取**摩擦圆使用率超出模式允许值**
的部分：模式的定义就是"可用抓地力里你能用几成"，比对的是指令本身而非代理量，无需按赛道标定。
使用率在整圆处截断——请求超过整圆不会换来抓地力，只会打滑，物理已经计价，不重复扣分
（对应"自费的极限不惩罚"）。抗命整回合约扣 8 分，而抗命多跑的里程只值约 0.5 分，
听话清晰占优。**每回合随机抽取 ego 的轮胎/电池模式**，否则策略只会见到 Attack，
观测里给了模式也学不出模式条件行为。

## 三、观测：452 维，track-agnostic

**防泄露铁律**：同一物理局面出现在任何赛道，观测必须逐位相同。禁止绝对 s、全局坐标、
赛道长度、圈数、赛道身份。验收：多赛道训练、留出赛道评估。

**第二条铁律（本轮补上）**：路面以**几何**给出，不以提取量给出。曲率标量是一次有损
压缩，压缩者没想到的东西会被静默丢掉——坡度、倾角、路拱、缓冲区、左右不对称，就是
这么在一台刚拿到 2.5D 世界的车上全部消失的。

**第三条铁律（本轮补上）**：凡属于车而非路的量，一律给**无量纲的比例**，是这辆车自身
包络的百分之几，而不是它的牛顿数。否则权重会悄悄变成"只认这一辆车"。

| 块 | 内容 | 维数 |
|---|---|---|
| 前方几何 | **按速度缩放到前方 6 秒**的 18 站，每站 左边线/中心线/右边线三点 (Δ前, Δ横, Δ高) + 该站左右缓冲宽度 | 198 |
| 轮胎与电量 | 四轮 表面温/核心温/磨损/**载荷** + SoC | 17 |

### 三之一、三个点为什么等于整条断面

路面横断面是 `z(d) = z0 + BankSlope·d + BankCurvature·d²`——三个系数。左中右三个已知
横向偏移上的高度**唯一确定**它：

```
BankSlope     = (z左 − z右) / (2·halfWidth)
BankCurvature = (z左 + z右 − 2·z0) / (2·halfWidth²)
```

所以给点不是给断面的采样，是给断面的全部。坡度是 z 沿 s 的爬升，倾角与路拱是两条边线
的高度差，宽度是两点的间距——四样东西共用一个通道，网络不必为每样学一个新含义。
`ZandvoortTests` / `DirectDriveRaceDriverTests` 把这条反解钉到小数点后四位。

### 三之二、视界按秒不按米

前瞻站点跨度 = `max(60 m, 速度 × 6 s)`。固定米数的数组两头都在浪费：20 m/s 时 600 m
那个点是三十秒之后的事，60 m/s 时 2 m 那个点是 0.04 秒之后的事，而且**输入分布会随速度
漂移**——同一个"下一个弯"在不同速度下落在不同通道上。按秒缩放之后每个槽位的含义与
速度无关，刹车预警距离自动跟上。这是 Sony 的做法（"approximately the next 6 s of travel"）。

### 三之三、被罚的量必须看得见

本轮最贵的一个洞：`mode_excess` 罚的是 `max(前轴使用率, 后轴使用率) − allowance`，
而**两个操作数策略一个都看不见**——allowance 只以五档序数出现，使用率根本没给。
同类问题还有两个：动作正半轴按每步变动的 `driveLimit` 归一化而负半轴按车的常数，
刻度换了没人告诉它；白线外是二十米柏油还是十九厘米护栏，读数完全一样。

规矩：**给推不出来的，不给现成能算的。** 据此刻意不给的有——`ReferenceYawRate`
（= 速度 × 指令曲率，两个量都在）、`OverLimit`（= 两个轴使用率的 max）、
`ActualCurvature`（≈ 横摆率 ÷ 速度）、绝对抓地力（给的是比例，换车才通用）。

长时程信息不用 RNN：短时看帧差，前瞻看对手发布计划，行为风格看手工 EMA 特征
（后续按需加入，每对手 2-3 维）。理由：运行时成本不是问题（GRU 也只有 GFLOP 级），
真实代价在训练管线复杂化（序列回放、burn-in、隐状态过期）与不可审计。

## 四、网络与性能预算

- MLP：452 → 512 → 512 → 256 → 动作头，含孪生分布式 critic 约 **167 万参数**；
- 项目性能前提（README）：二十辆车同场、CPU 实时——本预算满足并留有大量余量。

**推理开销（运行时唯一要跑的部分，CPU，批 64 摊薄）**：

| 网络 | 参数 | 单车 | 20 车一次决策 | 10 Hz 下占一个核 |
|---|---|---|---|---|
| **512/512/256（当前）** | **1.67M** | **0.010 ms** | **0.19 ms** | **0.19%** |
| 1024/1024/512 | 5.71M | 0.021 ms | 0.42 ms | 0.42% |
| 2048×2（论文单圈网络） | 14.6M | 0.050 ms | 0.99 ms | 1.0% |
| 2048×4（论文比赛网络） | 39.8M | 0.12 ms | 2.4 ms | 2.4% |

60 fps 一帧 16.7 ms、策略每 6 帧跑一次，就算上到 2048×2 也只占那一帧的 6%。
**推理不是约束，训练墙上时间才是**——同一张表按更新耗时算，2048×2 是当前的 4.9 倍、
2048×4 是 11.9 倍，300k 步从 2.7 小时变成 13 小时和 32 小时。

**设备**：默认 CPU。早期"Metal 不划算"的结论（更新 GPU 10.2 ms 对 CPU 10.7 ms）是在
分布式 critic 之前测的，现已过时——同一台机器重测为 GPU 22.5 ms 对 CPU 46.9 ms，
MPS 约快一倍。但推理这一半 CPU 仍快（0.61 ms 对 2.14 ms），而推理是游戏里唯一要跑的
部分，所以默认仍取 CPU，`--device` 可覆盖。

**训练吞吐**：独占机器约 2000 tps，300k 步（1920 万 transitions）约 2.7 小时。
两条臂并行时各约 830 tps，合计 1660，仍比串行独占的单条更划算。

**容量还没到顶，别急着放大。** 判据是 critic loss：网络太小会在性能停止提升的同时
停止下降。300k 步全程 `closs` 在 0.2–0.9 之间持续波动下降，没有饱和迹象。

另一个尺度感——参数对样本：

| 网络 | 参数 | 300k 步（1920 万 transitions）下的样本/参数 |
|---|---|---|
| 512/512/256 | 1.67M | 11.5 |
| 2048×2 | 14.6M | 1.3 |
| 2048×4 | 39.8M | 0.48 |
| **GT Sophy 2048×4** | **39.8M** | **40**（16 亿 transitions） |

按论文自己的比例，当前网络对当前数据量已经偏大。要把 2048×4 喂到那个比例需要
**16 亿 transitions**，按 2000 tps 是 **8.6 天**——正好对上论文写的 "ten rollout
workers for about 8 days"。**真正的限制是一台笔记本能采多少样本，不是网络能有多大。**

### 四之二、为什么现在不上复杂架构

**原则：复杂度用来回应已诊断出的问题，不用来预防想象中的问题。**目前诊断出的
问题全是奖励设计漏洞（躺平零成本、进度权重过小），不是容量或表示能力不足；
此时加架构只会给下一次调试增加混淆变量。

**LLM 的 scaling law 不能直接搬过来**，四条前提我们都不满足：

1. **数据来源**：LLM 的语料是固定的人类成品，瓶颈在"能吸收多少"，加参数即加吸收力；
   RL 的数据是自己开出来的，加参数不产生经验，且分布由当前策略决定（策略烂则数据烂）。
2. **目标是否静止**：LLM 预测下一个 token，靶子永远不动，是监督学习；RL 的 critic
   目标包含自身输出（自举），策略一变分布也变——容量更大会更快更狠地拟合当前这个
   错误目标，放大误差（"致命三角"：函数近似 + 自举 + off-policy）。
3. **单样本信息量**：LLM 每个 token 都是精确标签；RL 一步只有一个标量，且大多数步
   只有 -0.003 的时间惩罚，信息量差几个数量级——所以瓶颈是样本不是容量。
4. **任务复杂度天花板**：建模全部人类文本无上限；"路形 + 车况 → 方向盘 + 油门"
   是光滑低复杂度函数，容量够表示之后再加就是浪费。

**但这不是铁律**：2024 年起有一批工作（BRO、Simba、CrossQ 等）证明 RL 网络可以放大
并变好，前提是加上 LayerNorm / 残差 / 更强正则。**朴素 MLP + SAC 确实不 scale，
但那是"朴素"的问题不是"大"的问题**——真要吃规模红利需要先换架构。

**两类升级要分开对待**（原表把它们混为一谈，是表述错误）：

**甲类，算法层面公认更优的默认值——开局就该抄，不必等触发。**已经在用的有：孪生
critic、自动熵调节、tanh 压缩策略。还该补的有分布式 critic（QR/TQC）与 critic 侧
LayerNorm：TQC 在 MuJoCo 上大幅超过普通 SAC，是连续控制的通用结论而非赛车专属，
改动约四十行。抄作业能抄到的是算法；抄不到的是问题定义（奖励、观测、动作频率）
与算力（GT Sophy 用上千台主机训练数日）。

**乙类，任务专属的架构——等诊断出问题再加**，否则只增加调试的混淆变量：

**候选升级与触发条件**（避免凭感觉加东西）：

| 观察到什么 | 才上什么 | 备注 |
|---|---|---|
| 奖励稳定但学习卡在基线之下 | 加宽网络 | 先确认不是奖励的问题 |
| 进入对局阶段后对手相关的学习明显低效，或名次交换处行为抖动 | 集合编码器（DeepSets / 注意力） | 见下 |
| 需要记住对手风格 | 手工 EMA 特征 → 最后才 RNN | 理由见第三节 |

**集合编码器的收益不止于抖动**：对手现按距离排序后拍平成 6×16 的定长向量，排序确实
消除了名次交换时的输入跳变，但没有解决更大的损失——"右前方八米有车切过来"这个概念
要在六个槽位上各学一遍，彼此不共享权重，样本效率平白差六倍。共享 φ + 求和池化天然
置换不变且概念只学一次；注意力更进一步，能建模对手之间的关系，并把"我想去的那块
空间有没有人"表达成查询，还顺带支持可变对手数（现在靠"在场标志"补空位是变通）。
不在单车阶段做，是因为那时对手块全为零，与当前瓶颈无关。

**QR-SAC 是最有针对性的一个**：过弯结果是双峰的（过去了 / 撞了），预测期望回报等于
描述一个不存在的结果，而分布式 critic 能表达"七成过、三成撞"，这对权衡风险有实质意义。
索尼那个胜过 GT Sport 顶尖真人的 AI 用的正是 QR-SAC，同任务同判断。

**甲类的引入顺序**：一次只改一样，否则分不清是谁的功劳。基线曲线跑完后依次做
A（分布式 critic）与 B（critic LayerNorm），各自与基线比同等墙上时间下的学习曲线。
之所以不在基线跑完前动手，理由不是"缺触发条件"而是实验卫生：当前仍在 debug 问题
定义（已抓出两个奖励漏洞），此时换求解器会让"没进步"归因不清。

**明确不采用**：模型 based RL（Dreamer/TD-MPC 一类）。它的卖点是用算力换样本，
而我们样本极便宜（12000 条/秒）、算力才是瓶颈——方向相反。

### 四之三、教练块已删除，而且学习司机已经越过它

原计划把解析栈的建议放进观测当"教练"，并担心它变成拐棍。这个担心不必要了：教练块
（建议曲率、建议加速度、自由计划速度，共 14 维）已从观测中**整体删除**，`ReferenceLineDriver`
也不再作为观测来源——它又慢又贵，而删掉之后策略照样学会了开车。

结果比预期好：在坡度 7.3%、倾角 19° 的两条 simple 赛道上，学习司机已经**超过**解析
司机（50.0 对 48.1、49.2 对 48.1，即 104% 与 102%）。原因正是下一节预言过的——解析
规划器的纵向摩擦圆是平路模型，坡与倾角带来的额外抓地力它不会用，而观测里看得见这两样
的策略会自己学出"这个弯可以多带速度"。

### 四之四、2.5D 物理（坡度与倾角）已完成

路线图第 5 项，已于 PR #37 合入 master。物理经三维投影逐项核对至小数点后四位，
覆盖坡度、倾角、垂直弯曲与纵向加速度的组合及反号情形。

| | |
|---|---|
| 平面约定 | `s` 是二维中心线弧长，所以速度是水平速度、曲率是水平路径的曲率 |
| 法向载荷 | `N/m = [g + v²(κ·bank + r)] / L`，`L = √(1+grade²+bank²)`，`r = d(grade)/ds` |
| 横向需求 | `(G/L)·v²κ − bank(g + v²r)/(L·G)`，`G = √(1+grade²)` |
| 纵向 | `a·G + grade(g + v²r)/G` |

当时曾漏掉横向平衡里的 `cos φ`——模型向轮胎索取了整个 `v²κ` 而不是它沿路面的分量，
在 31° 倾角上偏 14.3%，在 45° 上偏 29.3%。是拿教科书闭式解对照才发现的。

**已知未修（PR #37 里记录）**：规划器的纵向摩擦圆仍是平路模型（过坡顶时刹车能力
高估 4.5–15.8%）；跟车间距不看坡度；交接上限与控制器驱动上限对倾角无感（偏保守）。
这些是**解析司机**的缺陷，学习司机不受影响——上一节那 104% 正是从这里来的。

- **赛道划分**：

  | | 赛道 | 坡度 | 倾角 |
  |---|---|---|---|
  | **训练** | 银石、上海、赞德沃特、simple 左/右 | 0.5–7.3% | 2.5–20.2° |

  不够（"the straightforward application of self-play was inadequate"），他们用的是

### 五之二、α 不能照抄：量纲教训

论文把 α 固定在 0.01。这个数被原样搬过来，结果训出一条**七万步不动的平线**。

原因是**奖励量纲差 50 倍**：论文的进度奖励是米（`R = l' − l`，1.0 奖励/米），我们是
`OwnProgressRate = 0.02` 奖励/米。所以 α = 0.01 在他们那儿是回报的千分之二，在我们
这儿是**百分之五十**。一个把一半收入拿去买随机性的策略不会收敛。

它在外部长这样：八条赛道上全是 16.7–19.7 m/s，从倾斜椭圆到摩纳哥只差 3 m/s——一条
永久模糊的策略。而自动调节的那条起步慢得多，α 自己收敛到 0.001（换算到论文量纲是
0.05，量级对得上他们的 0.01），最后一路爬到基线的 95%。

```
                     控制臂(自调α)   实验臂(固定α=0.01)   本轮(自调α+新观测)
 10k 雪邦                 4.1              18.9                 12.6
 20k                      5.8              20.6                 19.9
 30k                     12.9              19.2                 37.1
 60k                     23.8              18.0                 44.7
 90k                     27.5              18.4                 43.7
140k                     31.2                —                  45.3
300k                       —                 —              ★  47.2
```

**教训写在这里，因为这个形状会复发**：论文的常数分两类——关于**时间视界和梯度**的
（n 步、γ、裁剪、频率）可以平移；关于**奖励大小**的（α，某种程度上还有 critic 裁剪
阈值）必须按自己的奖励量纲折算。抄数字之前先抄量纲。

### 七之一、单车毕业成绩（300k 步，单种子）

同样的 90 秒站立起步协议，学习司机 vs 解析司机：

| | 赛道 | 学到的 | 解析基线 | 占比 | 退赛 |
|---|---|---|---|---|---|
| 训练 | **simple-right** | **50.0** | 48.1 | **104%** | 0 |
| 训练 | **simple-left** | **49.2** | 48.1 | **102%** | 0 |
| 训练 | 银石 | 50.8 | 56.5 | 90% | 0 |
| 训练 | 上海 | 46.2 | 51.7 | 89% | 0 |
| 训练 | 赞德沃特 | 44.6 | 49.9 | 89% | 0 |
| **保留** | **雪邦**（同分布） | **47.0** | 49.6 | **95%** | 0 |
| **保留** | 摩纳哥（坡度外推） | 24.4 | 40.6 | 60% | 0 |
| **保留** | speedway（平椭圆） | 57.0 | 75.5 | 75% | 0 |

单位 m/s。八条赛道**零退赛、零撞墙**，终止原因全部是跑满时间。

**成立的部分：**

- **在两条 simple 上超过了解析司机**（104% / 102%）。那是坡度 7.3%、倾角 19° 的两条，
  解析规划器的平路刹车模型在这里吃亏，而观测里能看见坡和倾角的策略把便宜占了。
  这是"学习方案有望超过解析方案"第一次拿到证据，而且落点正是四之四预言的地方。
- **没有背题**。留出的雪邦 95%，比它训练过的上海（89%）和赞德沃特（89%）还高。
  同分布留出赛道上的泛化间隙实际为负。
- **稳**。300k 步全程零退赛，最后一万步的分项里 `wall = −0.0000`、`off_course = −0.0003`。

**不成立、要继续做的部分：**

- **摩纳哥 60%** ——最窄（10.5 m）且坡度外推（8.6% > 训练上限 7.3%）的一条，是明确短板。
- **speedway 75%** ——极限速度场景，训练集里没有 3 km 长直道，学不到那一段。
- **倾角外推没测**（见五、赛道划分的注）。
- **单种子、单车**，没做重复性检验，轮对轮一次没练过。
- 95% 的对象是一个**拿到全赛道 QP 最优线**的规划器，不是物理极限。

### 七之二、本轮之前的三条死路（留档，避免重走）

1. **奖励在给慢速发钱**：跑得快挣的钱比动作平滑罚的钱少，曲线先涨后跌到 21.1 封顶。
   动作平滑罚已删除——论文根本没有动作幅度或动作变化的罚项，取而代之的是轮胎滑移罚。
2. **α 照抄论文**：见五之二，七万步平线。
3. **观测缺项**：坡度、倾角、缓冲区、动作刻度、罚分的两个操作数全部不可见。诊断特征
   是"速度跟着赛道宽度走而不是跟着弯速走"——半宽是当时唯一的余量信号。
