# 银石专家训练回退诊断 · 2026-09-05

## 结论与证据边界

确认存在训练步与司机决策时钟错位：同一状态下提交相反动作，可以得到完全相同的 452 维下一观测，但实际物理状态和奖励已经不同。这是当前训练管线的确定缺陷，也是应优先处理的项目；目前尚未用修正管线进行长训练，因此不能断言它解释了所有长期性能回退，更不能据此确认“灾难性遗忘”。

同条件复测确认后期检查点更慢、转向变化更多、胎耗异常。固定策略档位、临时取消磨损、直接把旧权重接到对齐后的环境，都没有消除早晚检查点的差距。

本次主树新增诊断材料，未修改生产 C#/Python 训练实现或原有检查点。所有 C# 实验在 `/private/tmp/stintegy-diagnosis-20260905` 副本进行。没有启动长训练，也没有完整重跑工程测试套件。

## 1. 已确认：训练 transition 的时序不一致

涉及：

- `Training/StintegyEVO.TrainingHost/Environment/DirectDriveDuelEnvironment.cs:357–364`：提交 manual action，推进 100ms，再返回司机缓存观测。
- `Core/Drivers/Learned/DirectDriveRaceDriver.cs:76–85,127–145`：司机另有 10Hz 决策时钟；先构造观测，后读取策略动作。
- `Core/Racing/RaceSimulation.cs:60–94`：100ms 环境步内分为六次约 16.67ms 的司机更新。
- Reset 中的微小 warmup 已经执行一次司机决策，导致环境步和司机时钟错开。

原始路径的实测时间线：

| 一个 100ms 环境步中的时间 | 实际发生的事 |
|---|---|
| 0–83.33ms | 保持上一条动作 |
| 约 83.33ms | 采集将被返回的观测，然后采用本次提交的动作 |
| 83.33–100ms | 本次动作开始影响物理 |
| 步末 | 奖励覆盖整个 100ms；返回的观测仍来自约 83.33ms |

因此相邻两个返回观测之间的物理演化主要对应上一条提交动作，Python 却把它记到当前动作下。观测中的“上一条动作”字段在新动作被读取前写入，也没有完整表达这段待执行动作状态。单纯把它叫作反应延迟，并不能保证 SAC 使用的状态、动作、奖励、后继状态具有一致语义。

**决定性对照**：两个相同种子的环境先执行同样的一次油门，再分别提交全油门和全刹车。

| 读数 | 原始路径 |
|---|---:|
| 两份返回观测的最大绝对差 | 0，全部 452 维相同 |
| 油门分支的实际末速度 | 50.67157 m/s |
| 刹车分支的实际末速度 | 50.01353 m/s |
| 奖励 | 0.100600585 / 0.09599011 |

隔离修正让每个环境步开头采用新动作、步末采集独立的完整观测，包含当前已执行动作与上一采样时刻的动态块。修正后的探针返回不同后继观测，返回速度等于实际末速度，每个子步都执行本次动作。

这验证了时序修正，不等于验证长训练收敛。实验补丁仅支持 solo 后采样，未包含多人快照，**不能直接作为生产补丁合并**。正式实现需明确唯一的决策时钟、动作生效区间、观测采样时刻、奖励区间，并让训练与游戏推理采用同一语义；若保留反应延迟，应明确建模动作队列与可观测状态。

原始与修正记录：`timing.jsonl`、`timing-aligned.jsonl`；自动断言：`verify_probes.py`、`verification.json`。

## 2. 已复现：后期驾驶策略确实退化

检查点为 `bestsp1.pt` 和 `latestsp1.pt` 的副本，SHA-256 见 `checkpoint-sha256.json`。同一份当前 C# 快照、同一赛道、相同初始种子对比；固定档位实验均为 Normal/Normal，其他环境随机数仍按相同种子取值。

每模型 8 个 lane、每 lane 400 秒，丢弃开始时不完整的圈，按冲线插值计时。下表是**所有完整圈的算术平均，包含出界圈**，用于比较回退而非宣称合法竞速水平；按 lane 平衡的统计也保存在 `summary.csv`，结论相同。

| 对照条件 | 早期平均完整圈 | 后期平均完整圈 | 差值 |
|---|---:|---:|---:|
| 原始随机档位 | 116.296s | 131.086s | +14.790s |
| 固定 Normal/Normal | 116.611s | 131.124s | +14.513s |
| 固定档位，每步把磨损设为 0 | 116.586s | 132.043s | +15.457s |
| 固定档位，改用对齐时序，权重不变 | 115.610s | 130.652s | +15.043s |

Normal/Normal 下的其他观测：

- 400 秒末四轮平均磨损：早期约 19.2%，后期约 99.8%。
- 相邻决策归一化转向动作变化绝对值的均值：0.00649 → 0.01970，约 3.0 倍。这是曲率请求变化指标，不是方向盘角度。
- 每 lane 出界累计：约 5.86 秒 → 1.89 秒。后期虽然更少出界，仍更慢，不能把出界减少当作整体驾驶进步。
- 取消磨损后，后期仍慢且转向变化继续偏大。该干预也改变观测和后续温度，不能证明磨损完全无影响，但排除了“只要磨损不掉就恢复早期配速”的解释。
- 用训练时的随机动作而非确定性均值，复测 240 秒：早期平均完整圈 145.193 秒，后期 151.333 秒；完成圈分别仅 5 和 3，统计把握有限，但回退也出现在随机策略执行中。

分段时间估计显示损失分布在多段路段，不能仅凭这些结果断定遗忘了某一个弯。没有采用“给动作加平滑罚”或换算法作为未经验证的修复。

## 3. 已确认：原评估不足以判定毕业或泛化天花板

`train.py` 的 `evaluate()` 把完成圈时间加入同一列表，未按该圈出界/碰墙情况剔除，然后取所有 lane 的 `min(laps)` 作为圈速；默认评估只有两个 lane，策略档位由 reset 种子随机决定。

本次固定档位对照中，早期 19 个完整圈没有一圈满足“该圈无出界罚、无墙罚”；后期 16 圈中只有 1 圈满足。这一干净圈定义使用现有环境的罚项判定，并不构成完整赛会规则。

解析基线是 TRACKS 表中的固定数字，当前评估没有重新生成与相同档位、车况、环境和决策频率匹配的解析对照。因此，不能用日志中的单个 gap 直接判定容量上限或专家失败原因。这不推翻本次同条件早晚权重比较得出的回退事实。

另一个边界问题是任一 lane 结束后 `previous = None`，会让其他 lane 下一步也跳过冲线检查；本次确定性 8-lane 对照没有 terminal，因此它不是本次圈速差的来源。

建议正式评估分别报告干净完圈率、逐 lane 干净圈分布、出界/事故、指令合规、资源状态；匹配比较条件后再使用解析基线。最佳模型选择不应仅由一个最快的非合规圈决定。

## 4. 已确认：resume 是热启动，不是完整续训

`sac.py:419–435` 只保存 actor、critic 和 log_alpha；load 把 target critic 重设为当前 critic。没有保存 replay、优化器状态、随机数状态、n-step 队列或训练进度。

`train.py:292–299` 从第 1 步重新计数，恢复后仍可能执行前 10,000 transitions 的全随机动作。`--seed` 被传入环境和评估，但没有设置 NumPy/PyTorch 的训练随机种子。

这些是复现及热启动稳定性的风险，能影响 `sp2-warmstart` 的解释；**不能拿它们解释从头开始的 sp1 长训练回退**。后续实验必须明确区分完整续训与新回放池热启动，并保存实验清单。

## 5. 本次检查通过的部分与尚未确定的机制

对现有 NStepBatcher 做了独立合成检查：折扣累计、timeout 保留 bootstrap、真正 terminal 截断、lane 隔离、尾部 horizon 均通过。这是针对性检查，不是完整算法认证。

尚未证实：灾难性遗忘、可塑性丧失、网络容量不足、回放分布变化或某个 QR-SAC 更新选择，是长期退步的具体主因。所有性能比较都没有更新权重；修正时序后旧模型未恢复，正说明不能把时序缺陷直接等同于已完成的学习根因闭环。

**下一步顺序**：先修时序与评估契约并补回归测试；再用固定一车一赛道的受控训练，对原管线与修正管线采用相同预算和明确的随机种子进行比较。完整续训与热启动分别标注，至少采用多个独立训练种子；同时监控逐段速度、转向变化、胎温胎耗、有效完圈率和回放覆盖。只有仍然回退且证据指向学习机制时，再决定是否修改回放或网络。
