# StintegyEVO – 赛车策略工程师模拟器

[English](README.md)

_维护者会尽合理努力保证中英文版本一致。如果仍存在无法消除的不一致，以中文版为准。_

**StintegyEVO** 是一款**由实时车辆物理驱动的赛车策略模拟游戏**。你扮演的不是车手，而是**赛车工程师**。你的工作是在正赛、排位赛和耐力赛中调整轮胎使用、电池功率等策略，指挥 AI 车手执行战术，并在同一套车辆物理中承担这些决策的后果。四轮扭矩矢量、可调能量回收、电机热管理和更详细的非线性轮胎模型属于长期演进方向。

> **注意：你不需要手柄或方向盘。** 所有驾驶操作都由 AI 车手完成，你只需要下达策略指令。

> **基本前提不会改变：AI 车手是在开一辆真实参与仿真的车。** 规划、控制、轮胎、电量、碰撞和赛道边界共享同一份车辆状态，而不是分别播放互不相关的动画或预设结果。

## 🤝 欢迎聚焦协作

StintegyEVO 仍处于早期工程开发阶段，目前是一套**可以运行和观察的工程原型**，还不是内容完整的游戏。车辆物理、AI 基础驾驶、车辆实际运动路径预测、滚动局部速度规划和固定路径上的纵向避让已经形成闭环；当前重点是让 AI 在多车环境中选择稳定的局部攻防路线，并逐步补齐比赛流程和策略界面。

仓库保持公开，也欢迎围绕具体问题协作，但项目仍由维护者主导，且处于探索阶段。在第一个稳定原型形成前，玩法范围、物理复杂度、AI 架构和路线优先级都可能继续变化。

当前最适合协作的方向包括：

*   **车辆控制与 AI**：局部路径候选、碰撞约束、超车与防守、赛车 AI，以及其他可实时运行的规划与控制方案。
*   **车辆动力学**：当前降阶模型的仿真验证、性能包络，以及未来更详细的轮胎、动力和能量模型。
*   **Godot 4 / C# 工程**：仿真架构、性能分析、测试、遥测和调试工具。
*   **美术与界面设计**：低多边形赛车、比赛工程师工作台、遥测可视化和技术展示。

你不需要独自解决整个系统。架构建议、可复现实验、性能测试、局部实现，以及能够说明问题的失败方案，都是有价值的贡献。

## 🚀 核心特性

### 1. 可实时运行的电动赛车物理核心

当前模型有意采用面向二十辆车同场运行和在线规划的降阶表达，但所有关键状态都会持续演化：

*   **抓地力与车身动态**：前后轴独立摩擦圆、纵横向载荷转移、横摆与车身侧偏、后轴侧滑、牵引力控制及侧滑能量损失。
*   **四轮轮胎记账**：四条轮胎分别记录载荷、表面温度、核心温度和磨损；实际受力目前在前后轴层面聚合计算。
*   **电池与动力**：功率—车速约束、电池 SOC、低电量功率衰减、能耗和再生制动，并提供五档功率预设及连续调节基础。
*   **赛道与碰撞交互**：车辆边界、车墙碰撞、车车碰撞和碰撞后的状态恢复均进入同一仿真循环。

### 2. AI 策略执行（原型已可运行）

你的 AI 车手目前能够：

*   **跟踪赛车线**：使用 Stanley 控制律从车辆实时位置和姿态生成目标曲率。
*   **预测实际走向**：向前展开同一套控制律产生的车辆运动路径，而不是假设车辆始终位于静态赛车线上。
*   **滚动速度规划**：在局部预测路径上根据曲率、轮胎状态、电池功率和纵横向总加速度约束进行前向/后向传播。
*   **纵向避让**：每辆车只读取同一帧冻结的对手状态，独立预测冲突并选择跟车或停车，不依赖其他车辆的规划结果。
*   **车手差异**：速度、稳定性、车辆控制、轮胎管理和适应能力已经接入规划、控制与物理结果，并带有可复现的随机波动。

横向超车、防守和并排行驶仍在路线图中；当前避让只会沿已有路径调整速度。

### 3. 策略深度
当前仿真已经支持并正在标定：

*   轮胎使用强度：Protect、Light、Normal、Push、Attack 五档预设及连续插值。
*   电池输出功率：Save、Eco、Normal、Push、Attack 五档预设及连续功率上限。
*   轮胎温度、磨损、电量和车手能力共同作用于圈速，而不是只改变 UI 数字。

长期计划在同一策略框架内加入前后轴及左右轮扭矩分配、动能回收强度、电机热管理、空气动力学和尾流博弈。

### 4. 开源 & 可扩展
*   仿真核心完全自研，不依赖 Godot 节点生命周期，可独立构建、测试和运行。
*   赛道数据基于曲线定义，易于社区创建新赛道。
*   社区版本以 **AGPL-3.0** 开源。贡献者保留自己作品的版权，已经接受的贡献会继续保持开放。

## 🧠 设计理念

赛车游戏通常让你当车手。但真正的赛车比赛，胜负往往在 Pit Wall 上决定。StintegyEVO 想让你体验的是**那个拿着战术板的人**。你不需要有零秒反应速度，但你需要理解轮胎、电机、电量和空气动力学的博弈。

### 🆚 与其他赛车游戏的定位差异

| 维度 | Motorsport Manager | F1 Manager 2024 | iRacing | **StintegyEVO** |
|:---|:---|:---|:---|:---|
| **定位** | 赛车经理经营模拟 | F1官方车队管理 | 硬核驾驶模拟 | **赛车策略工程师模拟器** |
| **物理引擎** | 简化数值模型 | 游戏级物理 | 高拟真驾驶物理 | **自研实时车辆动力学** |
| **动力系统** | 传统内燃机 | F1混合动力（抽象化） | 内燃机/混合动力 | **现代电动赛车** |
| **驾驶方式** | AI自动 | AI自动 | 玩家亲自驾驶 | **AI车手执行，玩家下达策略指令** |
| **策略深度** | 进站/轮胎/引擎模式 | 进站/轮胎/ERS | 赛道竞技 | **当前为轮胎使用与电池输出；逐步扩展车辆和能量控制** |
| **轮胎模型** | 简化磨损 | 游戏级 | 高拟真驾驶轮胎 | **前后轴摩擦圆 + 四轮双层温度与磨损** |
| **可扩展性** | Mod支持 | 有限 | 封闭生态 | **开源（AGPLv3）** |

### StintegyEVO 为什么选择这条路线？

- **传统驾驶模拟器（iRacing/ACC/Forza）让你当车手。** StintegyEVO 让你当赛车工程师。
- **赛车管理游戏强调车队与比赛决策。** StintegyEVO 进一步尝试让轮胎、电池和车辆状态在实时仿真中产生策略后果。
- **StintegyEVO 是两条路线的交叉实验：** 它追求《Motorsport Manager》式的战术视角，也保留一套可以持续加深的车辆物理核心。当前仍是早期原型，不宣称达到专业驾驶模拟器或工程仿真的精度。

## 🛠️ 技术栈

*   **引擎**：[Godot Engine 4.6.x](https://godotengine.org/)（.NET 版）
*   **语言与运行时**：C# / .NET 8
*   **核心**：与 Godot 表现层分离的 2D 车辆、比赛和规划仿真，可无界面运行自动化测试
*   **表现层**：当前为 Godot 2D 调试与比赛视图，Low Poly 3D 属于后续计划
*   **AI**：Stanley 跟踪、车辆运动路径预测、滚动局部速度规划及基于共享状态快照的交通约束
*   **数值工具**：使用 HiGHS 与 BLAS 支撑最小曲率参考线优化

## 🗺️ 路线图

StintegyEVO 是一个个人独立开发的项目。目前已经跨过“AI 能否稳定把车开起来”的首个阻塞，形成了从车辆状态、路径预测、速度规划到物理执行的可运行闭环；下一阶段转向多车环境下的局部路线选择、攻防行为和游戏化界面。

### ✅ v0.1 可运行车辆物理（已完成）

- 前后轴独立摩擦圆与纵横向抓地力竞争。
- 四轮载荷转移，以及四条轮胎各自的表面温度、核心温度和磨损记账。
- 横摆、车身侧偏、后轴侧滑、牵引力控制及侧滑能量损失。
- 电池功率限制、SOC、能耗、再生制动和五档电池输出模式。
- 车辆与赛道边界、车辆与车辆之间的碰撞处理；赛道边界使用扫掠检测降低高速穿墙风险。

### ✅ v0.2 AI 基础驾驶与动态速度规划（已完成）

- 使用最小曲率参考线和 Stanley 控制律稳定完成赛道。
- 从车辆当前真实位置、航向、侧偏和横摆状态向前预测控制器实际会走出的路径。
- 在预测路径上进行滚动局部速度规划，同时考虑曲率、动力、制动、轮胎状态及摩擦圆约束。
- 速度规划每帧更新局部窗口，不要求对整条赛道持续重算。
- Pace、Consistency、Car Control、Tire Management 和 Adaptability 已经影响规划、控制或物理结果。

### ✅ v0.3 纵向多车避让（阶段性完成）

- 所有车辆读取同一帧冻结状态并独立规划，不读取或等待其他车辆的规划结果。
- 根据对手当前运动状态进行短期预测，通过车身包围盒和扫掠检测发现潜在冲突。
- 冲突约束直接接入滚动速度规划，支持慢车跟随和静止/横穿车辆前停车。
- 当前阶段只调整速度，不生成横向超车或防守路线。

### 🚧 待实现（按建议优先级排列）

#### 1. 局部攻防路径（当前焦点）
_依赖：v0.2、v0.3_

- 在当前参考路线周围生成保持、左移、右移等少量可解释候选。
- 对每条候选同时检查赛道边界、车辆冲突和可实现的速度规划，而不是先选路线再临时刹车补救。
- 继承上一帧尚未走完的有效路径，并使用切换滞回抑制逐帧重规划形成的负反馈。
- 每辆车仍只依赖共享状态快照，使多车规划可以并行执行。

**阶段目标**：先得到稳定、快速、不会左右摇摆的并行/绕行能力，再在其上定义超车收益、防守意图和赛车规则。

#### 2. 完整策略控制台
_依赖：v0.2_

- 将现有轮胎使用强度和电池功率的五档预设接入连续滑条与赛中操作界面。
- 展示轮胎表面/核心温度、磨损、电池 SOC、功率、车辆稳定性和规划状态。
- 随着高级车辆模型落地，再加入扭矩分配、回收强度和热管理等策略控制。

#### 3. 车手比赛能力与攻防决策
_依赖：1_

- 继续接入 Reactions、Awareness、Overtaking 和 Defending，使其影响冲突发现、路线选择和决策时机。
- 保留“低能力也可能偶尔发挥出色，但波动更大”的随机模型。
- 策略和资源管理仍由玩家负责；车手能力主要描述把车开好和执行战术的水平。

#### 4. 高级车辆模型（长期方向，非当前焦点）
_依赖：v0.1_

高级物理不会要求 AI 车手直接输出方向盘角度或四个电机扭矩。计划保持稳定的控制边界：

```text
AI 车手：目标曲率、目标加速度
              ↓
车辆底层控制器：转向角、四轮扭矩、机械/再生制动分配
              ↓
详细车辆物理：轮胎力、横摆、轮速、电机、电池与热状态
```

- 增加车辆执行器分配层，把语义化驾驶目标转换为实际转向、驱动和制动命令。
- 引入四轮独立扭矩矢量控制、可调动能回收混合和电机热衰减。
- 评估包含联合滑移、力松弛和轮速状态的非线性轮胎模型；Pacejka 是候选方案，而不是为了宣传而锁死的实现。
- 运行时可以使用更详细的物理，规划器和车辆运动预测则继续使用由同一车辆参数标定的低阶性能包络，避免每个路径采样点都运行完整轮胎模型。

#### 5. 赛道坡度与倾角
_依赖：v0.1_

- 赛道数据支持坡度和倾角，并进入载荷、纵向加速度及过弯能力计算。
- 由车辆性能包络向规划器暴露影响，避免规划层重复实现一套物理。

#### 6. 比赛周末框架
_依赖：1、2_

- 练习赛、排位赛、正赛的完整流程。
- 轮胎选择、进站和调校预设。
- 从“跑一圈”扩展到“管理一场比赛”。

#### 7. Low Poly 3D 画面
_依赖：无（纯表现层）_

- 基于 Godot 的 3D 渲染层，配合独立的 2D 仿真核心，探索《Art of Rally》式的低多边形视觉。
- 比赛工程师工作台、策略操作和遥测面板。

#### 8. 赛道编辑器原型
_依赖：5_

- 玩家可创建和导入赛道，参考线优化、AI 驾驶和局部规划复用同一套赛道数据。
- 社区内容生态的基础设施。

### 🌟 长期展望（社区的想象力）

- 多人模式：多名玩家各自指挥自己的车队同时在线竞技。
- 高级赛事模拟：安全车、虚拟安全车、动态天气、路面温度和积水。
- 生涯模式：完整的车队经营、研发树、车手市场。
- 硬件在环接口：对接真实车辆数据采集系统，或将引擎输出至专业模拟软件（为工程化应用预留可能）。

## 🏁 快速开始

克隆仓库并验证独立仿真核心：

```bash
git clone https://github.com/MoYuSOwO/stintegy-evo.git
cd stintegy-evo
dotnet build StintegyEVO.sln
./test.sh
```

运行默认演示时，请使用 Godot 4.6.x .NET 版打开 `project.godot`。当前默认场景会展示一辆车在固定路径上识别并跟随前方慢车。开发环境需要 .NET SDK 8.0+。
